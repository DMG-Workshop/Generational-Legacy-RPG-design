# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Godot 4.7 with GDScript. Commands assume `godot` is on the PATH.

- Import assets and scripts (once in a fresh checkout): `godot --headless --path . --import`
- Play the game: `godot --path .` (main scene `ui/main.tscn` loads `main.gd`, which starts `ui/play/game_app.gd`)
- Run one test suite: `godot --headless --path . -s res://tests/test_game_round.gd`
  - Exit code 0 means pass. A suite prints `N checks, M failures` (or `ALL PASS`) and exits 1 on any failure.
- Run every game suite, one after another:
  `for t in tests/test_game_*.gd tests/test_round_determinism.gd; do godot --headless --path . -s res://$t || echo "FAILED $t"; done`
- Never run suites in parallel on one machine. They share the `user://` save files and fail when they overlap.
- CI (`.github/workflows/tests.yml`) runs the same suites on every pull request, one job per suite. It also fails a suite that prints `SCRIPT ERROR` even when the exit code is 0. Look for that text when you run suites by hand.
- Debug Android APK: `godot --headless --path . --export-debug "Android" build/GenerationalLegacy-debug.apk` (the Android SDK and JDK are configured in Godot's editor settings). The iOS preset only exports on a Mac with Xcode.
- Check all the data at once: `godot --headless --path . -s res://tools/check_data.gd`. It parses every JSON file under `data/`, runs every system's `validate()`, and checks the text catalog; it prints the problems and exits 1 if there are any. `tests/test_game_data.gd` runs it, so CI does too. A new `validate()` goes into `tools/check_data.gd`.
- Replays: `godot --headless --path . -s res://tools/replay.gd -- record SEED CLASS RACE COMMANDS [FILE]` has the autopilot live a run and prints (or writes) its replay block; `-- play FILE` plays one and exits 1, saying where, if it no longer holds on this version of the game.
- Long run: `godot --headless --path . -s res://tools/long_run_check.gd -- [seeds=1-2] [gens=60] [races=human,elf] [check]` has the autopilot play whole dynasties for many generations and holds each to the budgets in `data/game/budgets.json` (save size, load time, time per generation, journal size, the line carrying on). `.github/workflows/long-runs.yml` runs it every night, one race per job, and can be started by hand. A change that makes saves, loading or generations much heavier shows up there; raise a budget only on purpose, in the same change.
- Screenshots: `xvfb-run -a -s "-screen 0 1280x720x24" godot --path . --rendering-driver opengl3 --audio-driver Dummy -s res://tools/screenshots.gd -- mode=check` draws the key screens with the real renderer on a virtual display and compares them with `tests/screenshots`; `mode=update` makes the stored images again. `.github/workflows/screenshots.yml` runs the check on every pull request and keeps what it drew as an artifact. A change that moves a screen or the art must update the stored images in the same change (tick "update" when starting the workflow by hand on the branch, or run `mode=update` locally); the diff of the PNGs is what the reviewer looks at.
- Rendering trial (throwaway, roadmap item 36): `godot --path . res://trial/iso_trial.tscn` runs it on a computer; the "Rendering trial APK" workflow builds it as its own Android app, and `tools/trial_adb.sh` records battery and temperature while it runs on a phone. It is left out of the game's builds. `docs/RENDER_TRIAL.md` has the method, what counts as a pass and the results table; nothing has been measured on a phone yet.
- Balance harness: `godot --headless --path . -s res://tools/balance_harness.gd` (the autopilot plays 12 seeds x 8 races x 10 generations, in parallel processes, about 4 minutes on 4 processors). Battle deaths should stay in the 3-7% band. Run it on the commit before a balance change and on the change with the same arguments; `docs/BALANCE.md` explains how to read the figures, which are noisy per seed.

## Architecture

Only the text game is wired into the app. The older prototype code is described at the end of this section.

- **Logic and rendering are separate.** `core/game/` makes no UI calls. `ui/play/` screens read dynasty state and call its methods, and they never compute results. New rules go in `core/game/` with a test in `tests/`.
- **Content is data.** `GameData` (`core/game/game_data.gd`) loads every JSON file under `data/` once, through `load_all()`. The tunable settings are in `data/game/balance.json` (Hard hunt rules, death chance), `data/combat/rounds.json` (party rounds), `data/classes/classes.json` (class skills, auto-battle `style`, openers) and `data/ui/mobile.json` (touch and layout sizes). Don't hardcode numbers in code.
- **State lives in `GameDynasty`** (`core/game/game_dynasty.gd`): the heir, the party, the world, the current battle, `command_round` and `auto_party`. It saves through `to_dict()` and `from_dict()`. A new field must load from an old save, and needs a test for that.
- **Battles.** `GameBattle` owns the round: heir, allies, foes, events and log. Its `round_on` hold lets manual party rounds use the same methods, and it is inert when no party round is open. `GameTactics.auto_turn` picks actions for auto-battle, the autopilot and any party member on Auto. `GameRound` queues manual party commands, resolves them together and retargets members who have died. A member's standing cover (`GameRound.set_cover`) is passed to the foe phase as `GameBattle.round_covers`; `_cover_for` redirects one blow a round aimed at a member below `cover_below`, drawing no dice, so a fight with no cover set plays exactly as before. With `GameRound.ask_reactions` on (only the battle screen sets it; tests, the golden scenarios and the autopilots leave it off), a foe about to strike a member below `cover_below` stops the round: `GameBattle.reaction` holds the blow, the foe phase waits in `_foe_queue`/`_foe_step`, and `GameRound.answer` strikes it and plays on. Letting it land draws no extra dice, so it plays exactly as a round that never asked.
- **Battle events.** The typed events a fight puts in `GameBattle.events` (and `GameRound` adds its round, act and foes markers to) are listed with their fields in `data/game/battle_events.json`; `GameEventSpec.problems` checks one against it. A new event, or a new field on one, goes on the list in the same change: `tests/test_game_event_list.gd` fails on an unlisted type or field and on a source type missing from the list. Life actions return text lines and emit no typed events.
- **Autopilot.** `GameBot` (`step`, `live_life`, `wants_hard_hunt`) plays without input for the tests and the "Auto" buttons. Changing when it or the battle draws a random number changes every seeded fight, and the determinism tests will catch that.
- **Determinism.** All randomness comes from the dynasty's seeded RNG. The same seed with the same commands gives the same result, including after a save and load between rounds. `tests/fixtures/round_baseline.json` is a golden file made by `tests/capture_round_baseline.gd`. Regenerate it only from the commit before a deliberate behaviour change, never to make a failing test pass.
- **World clock.** All passing of time goes through `GameDynasty.pass_time(years)` (ageing, party wages, disease, weather, the death roll, the Ages). Actions reach it with whole years; `GameClock.feed(d, seconds)` (core, no UI) is how a real-time world reaches it: seconds add up to `clock_span_years` spans (`balance.json` "clock_*"), the rest is carried in `GameDynasty.clock_carry` (saved only when above 0), and the clock holds still during a fight, a waiting event or a succession. A new per-year rule belongs inside `_pass_years`, never beside it, so both ways of passing time run it.
- **Replays.** `GameReplay` (core, no UI) records a run as its founding (seed, name, class, bloodline, race, sex) plus the commands given, with a fingerprint of the dynasty (as `to_save()` would write it, and the dice) every `check_every` commands and at the end, and plays it back to prove it. As text it is `GLRP1:` + base64 of the gzipped JSON, one line to paste. A command is `{op, ...}` from `GameReplay.OPS`; each is checked against the game's rules before it runs, so a damaged or hand-made replay is refused with a reason and never crashes. A new way for the player to change the game needs an op here (or it cannot be replayed). The recorder is used by the autopilot (`bot_on`) and the tests; the screens do not record yet. Changing what a command does changes what an old replay plays: that is a version change, and `GameReplay.play` says at which command the run first goes differently.
- **Creature birth.** `GameBirth` (core, no UI, pure functions of data) answers how creatures are born: each creature in `data/creatures/creatures.json` has `born` (`egg`, `live`, or `none` for what is not born and never bred: the undead, constructs, fiends, people-like foes) and, if born, `young` (the name of its young). `GameBirth.mode(mother, father)` says how a pairing's young are born: `kind` is `pure` (one species), `hybrid` (a recipe in `data/creatures/breeding.json` `recipes`, which says for itself how it is born) or `cross` (any other pairing of kin, which follows `settings.mixed_birth_rule`: `mother` by default, or `father`, `egg`, `live`); `young_of` names the young for the parent whose way they follow. The caller says which parent is the mother. A new creature needs `born` (and `young` if born); `GameBirth.validate` is part of `tools/check_data.gd`. Nothing here draws a die or touches the dynasty's state. `tests/test_game_birth.gd` tries all four rules and every pairing.
- **Finding young.** `GameFinding` (core, no UI) rolls whether a dead foe left an egg or young beside it, and `GameRoster` holds what the family keeps (`roster` on the dynasty, saved only when not empty, cleaned on load). The roll uses its own seeded dice (dynasty seed, hunt count, place), never the dynasty's, and the screens call `GameFinding.search_dead` in place of `GamePlague.search` (the battle result and the loot panel); the rules of a life never ask, so autopilot results and the golden digests do not move. Chances, rarity, class and trait bonuses (Wild Instincts, faetouched), the roster cap and the text are in `data/creatures/finding.json`, checked by `tools/check_data.gd`. Two more ways to find young: an event outcome can carry `find: {species: [...]}` (an effect key, validated: born creatures that are not legends; `GameFinding.take` picks one on dice keyed on the seed, generation and event), and the two nest and den events that use it **require the flag `found_young`** (set by the first creature the house takes in), so a house that has never found young is never offered them and the autopilot, which never does, sees an unchanged event pool; and a slain legend that is born may leave its young beside it (`GameFinding.after_battle`, asked by the battle screen's result, once per legend by the flag `legend_clutch_<id>`, `places.legend` times the base chance). The Beast Tamer job has no effect yet: there is no job mechanic (roadmap 60). The Chronicle's Creatures tab (`ui/play/chronicle_panel.gd`, text from `GameRoster.describe`) lists what is kept, with Sell and Set free (see Creature growth).
- **Creature growth.** `GameRanch` (core, no UI) ages the roster as the world clock passes: `GameDynasty._pass_years` calls `GameRanch.on_years`, so every way of passing time runs it. A creature is an egg (egg-layers only), young, adult, elder, then dies of old age; the lengths come from its size class in `data/creatures/ranch.json` (`size_of`, `sizes`), and the stage always follows `age` (saved with `mood`, and re-derived on load). Keeping costs gold a year from the heir (an egg half); an unpaid year sinks `mood`, and at 0 an egg spoils and a creature wanders off. **No dice are drawn** (an elder's end is stretched by a value from the dynasty seed and its id), and with an empty roster `on_years` returns at once, so autopilot results and the golden digests do not move. **The Ranch** is the house's third track (`GameHouse.RANCH`, bought like the others): the `ranch.levels` table in `ranch.json` gives each level its pens (added to `GameRoster.cap(d)`, which is the family's own places plus the pens, so never use the base `roster_cap` alone), a hatchery (eggs cost less to keep and sour slowly) and a nursery (the young the same); `GameRanch.ranch_factor` applies them and level 0 is exactly the old behaviour. A creature can be sold (`GameRanch.sell`, for its size's `value` by stage and mood) or set free (`release`); the Creatures tab asks twice before either. **Work:** grown creatures (an elder at half, none while unhappy, `work.min_mood`) do the work `work_of` gives their species: wool, eggs and venom pay gold each year (paid first, so a working ranch keeps itself), and guards turn away a share of the gold an event would take (`GameRanch.guard_cut`, applied in `GameEvents._apply`, 20% each up to 60%, and exactly nothing with no guards). The species mapping is a stand-in until farm animals exist (roadmap 62). Not built: farm animals (62), moods beyond keep, and party beasts. Raids are below. A new born creature needs a `size_of` entry and every size a `value` (`GameRanch.validate` checks).
- **Breeding.** `GameBreeding` (core, no UI; rules in `data/creatures/breeding_rules.json`, checked by `tools/check_data.gd`) runs from the end of `GameRanch.on_years`, so every way of passing time reaches it. A creature the player sets to breed (`breeding` on its roster entry; adult only) pairs with the first able creature of the opposite sex it is **compatible** with: the same species (`pure`), a species of its own family in `families` (a `cross`, which carries both parents' species in `lines`, is less fertile and likelier sterile) or a pair `GameBirth.recipe_for` knows (`hybrid`; the recipe's optional `species` is what is born; none ship yet, they need creature data and art). Each whole year the world clock crosses, each pair rolls on dice keyed on the dynasty seed, the year and the two ids, **never the dynasty's**: nothing in a life moves, and a ranch that breeds nothing does nothing. How the young are born is `GameBirth.mode` (the cross-breed rule); young keep the mother's species and `line`, inherit traits from either parent (`trait_pass_chance`, at most `max_traits`) and can mutate one; the mother rests (`cooldown`). Traits (`hardy`, `sickly`, `fierce`, `prized`, `industrious`, `fruitful`) change keep, price, work, guarding and fertility through `GameBreeding.trait_mult`. Roster entries gained `traits`, `breeding`, `cooldown`, `sterile`, and for bred young `bred`, `parents`, `line`, `lines`; all load cleaned (`GameRoster.load_list`). Not built: choosing pairs, hybrid species and their art, naming lines, and young going out with the party.
- **Subclasses.** `GameSubclass` (core, no UI; `data/subclasses/subclasses.json`, checked by `tools/check_data.gd`) is a calling layered on the heir's class: none or one (`GameHeir.subclass`, saved with `subclass_founded` only when there is one, an unknown id loading as none), never replacing the class's skills. It is **picked at the founding** (`GameDynasty.new_game`'s last argument, the title screen's pick, `GameApp.new_game`), **taken later** by the living heir for gold (`GameSubclass.take`; the price scales with the generation, a change costs double), or **passed to a child** (`GameSubclass.on_succession`, called from `choose_heir`, 50%, on dice keyed on the seed and the child, never the dynasty's). One chosen at the founding or inherited is *founded* and its perks are stronger (`founder_scale`); one taken later is at plain strength. A perk is a multiplier on a number the rules already have, read through `GameSubclass.perk(heir, key)` (1.0 with no subclass, so nothing moves without one): `find_mult` (GameFinding.chance), `keep_mult` (GameRanch.yearly_keep), `fertility_mult` and `mutation_mult` (GameBreeding), `value_mult` (GameRanch.sell_price, which now takes the dynasty). A new perk is a key in `perks` plus a place that reads it. The Chronicle's Subclass tab takes one; the life screen names it after the class. Only the Breeder exists; advanced subclasses of it and a full class born to it are not built, and replays do not record the founding subclass yet.
- **Raids.** `GameRaids` (core, no UI; `data/creatures/raids.json`, checked by `tools/check_data.gd`) is asked by `GameDynasty._pass_years` (after `GameRanch.on_years`), so every way of passing time reaches it. A house can be raided if it has **something worth taking**: animals in the pens, or a house that has been built (`house_value`: `house_value_share` of what each track's levels cost). A plain house with nothing kept and nothing built has no target, the chance is 0 and nothing is rolled, so the autopilot (which does neither) is untouched; raiding plain houses would be a balance change. Each whole year the clock crosses rolls on dice keyed on the seed and the year, **never the dynasty's**; the chance is `base_chance` plus `per_stock_gold` times the `valuables` (stock plus house), capped at `max_chance`, and cut by `deterrence` (the guards, `GameRanch.guard_cut`, up to `deter_share`; no animals, no guards, until hired guards exist). A raid is an **event** marked `raid: true` in `events.json` (`raid_thieves`, `raid_rustlers`, `raid_beasts`, `raid_burglars`, one per kind in `raids.json`): `GameEvents.is_eligible` never offers them while exploring, `GameRaids.on_years` begins one (never while another waits, and only a kind with something to take: thieves need gold, burglars a carried item, rustlers and beasts an animal; `GameEvents.explore` no longer overwrites one that came with the year), and the heir settles it on the event screen. The outcome effect `defend: <kind>` is trusting the guards: `GameRaids.defend` beats the raid off with `beat_off_chance` (0 with no guards, up to `beat_off_max`) or it takes what it came for (thieves a share of the gold, cut by the guards' `guarded_loss`; burglars a carried item; rustlers an animal; beasts kill one). Other choices pay, trick (a skill check, failing into `defend`) or ride out and fight (a `fight` outcome). Not built: renown and infamy changing the chance, hired guards and walls, raids on a plain house (a balance decision), and raiders beyond these four.
- **Farm animals.** `GameFarm` (core, no UI; `data/creatures/farm.json`, checked by `tools/check_data.gd`) is the worth of the creatures flagged `farm: true` in `creatures.json` (sheep, cattle, pigs, chickens, with art in `data/art/creatures.json` held to the usual style). **Farm animals are never fought and never found beside the dead**: the hunt's and the events' creature pools filter `farm` out (`GameDynasty.start_hunt`, `GameEvents._in_era`/`_creature_for`, the event validator), so every seeded fight and the golden digests are unchanged. They are **bought young at a town's market** (`GameFarm.buy`, flat prices, the name and sex keyed on the seed and what is kept, a bird skipping its egg), raised and bred like any creature (they have sizes in `ranch.json` and families in `breeding_rules.json`), give **wool, milk or eggs** each year through `work_of` (the pay follows the season, `season_mult`, and how well the animal is kept, `mood_scale` from the `mood_floor` to 1: `GameFarm.yield_mult`, read by `GameRanch.yearly_work`; wild creatures' work is untouched), and can be **slaughtered** for meat and hide once, past their egg (`GameFarm.slaughter`, paid by stage and mood, ending the animal). The Creatures tab has the Market (buy buttons, shut away from a town with the reason shown) and a Slaughter button asking twice. A new farm animal needs creature data with `farm: true`, art, a size, a family, a market price and meat and hide (`GameFarm.validate`). Not built: goats, geese, horses and bees, the market varying by place, and trade.
- **Titles.** `GameTitles` (core, no UI) reads `data/titles/titles.json`: each title has a `kind` (`personal`, ending with the heir and kept in their lineage record, or `house`, kept by the dynasty), an `about` that says how it is earned, a `when` condition read from the dynasty's own state (`stat` with `gte`/`lte` from `GameTitles.STATS`, `boss`, `boss_by_heir`, `flag`, `trait`, `class`, `race`, `family`, and `all`/`any`/`not`) and an optional `perk` (only `persuasion`, cheaper shops, while worn; `GameItems.persuasion` adds it). Earned ids are saved only once there is one (`GameHeir.titles`, `title_worn`, `GameDynasty.house_titles`, and `titles` in a lineage record) and load cleaned of anything unknown. **Earning is asked for by the screens** (`GameApp.show_state` and the life screen's `_changed` call `GameTitles.announce`), never by the rules of a life: the autopilot and the golden scenarios earn nothing and draw no die for it, so their results do not move. A new condition kind needs its branch in `met` and `_cond_problems`; `GameTitles.validate` is part of `tools/check_data.gd`. The Chronicle's Titles tab lists earned and unearned titles and puts one on or off. `tests/test_game_titles.gd` checks all of it, including that every title can be earned.
- **Tutorial.** The first-heir tips are chosen by `GameTutorial` (core, no UI) from the dynasty's own state, using the rules and text in `data/ui/tutorial.json`; nothing of it is saved, so it works on old saves. Only whether the tips are on lives in `user://settings.cfg`. The strip (`ui/play/tutorial_tip.gd`) is one row on purpose: a phone at large text has no height to spare. A new tip needs a `when` that includes `first_generation` and text of 125 characters or fewer; `tests/test_game_tutorial.gd` checks both.
- **Text in data.** The fight's log lines are in `data/text/battle.json`, found by key through `GameMessages.line(key, {placeholders})` (core, no UI). Add a line as a new key and a call, never as a string in code: `tests/test_game_data.gd` spells out every line word for word, fails if a `_say("...")` literal returns to `game_battle.gd`, and `tools/check_data.gd` fails on a key the code asks for that the catalog lacks, or one nothing asks for. Not yet moved: the life actions' messages in `game_dynasty.gd`, `game_events.gd`, `game_party.gd` and the rest of `core/game` (roadmap item 28 goes on).
- **Save slots.** `GameSaves` (core, no UI) owns the slot files: slot 1 is the original `user://dynasty_save.json`, the others add `_2`, `_3` (`balance.json` "save_slots"). `GameDynasty.save_path` stays "the file in use"; `GameApp.use_slot` points it at the chosen slot, so saving and loading are unchanged. Saves are written atomically and keep the one before as `.bak`, which loading falls back to. A backup is `GLBK1:` + base64 of the gzipped save, copied to and from the clipboard (`ui/play/clipboard.gd`, which tests fake) or written to and read from a `.glsave` text file holding the same block (`GameSaves.export_file`/`import_file`; `ui/play/file_picker.gd` uses the platform's file dialog where there is one, else the Downloads or `user://exports` folder, and tests fake it); `GameSaves.import_text` checks the shape before anything is loaded. If the save format gains a required key, add it to `GameSaves.REQUIRED` only when old saves have it too. The file is written by `GameDynasty.to_save()`: `to_dict()` (the shape the golden digests use, never changed by this) at the version in `GameSaveVersion.CURRENT`, plus a fight in progress under `"battle"` (`GameBattle`/`GameRound` `to_dict` and `restore`, in Godot's exact binary encoding as base64, values only), so a game closed mid-fight reopens in the same fight and plays on as if never saved. `GameSaves` runs `GameSaveVersion.upgrade` before `from_dict`: one tested step per version; a save from a newer game is turned away. A format change needs a new version and its step.
- **Family house.** `GameHouse` (core, no UI) holds the three upgrade tracks, Hall (companion places), Yard (training XP) and Ranch (pens, hatchery and nursery for the creatures, see Creature growth), bought with the heir's gold and stored on the dynasty as `house` (only once something is bought). Costs and effects are in `balance.json` (`house_*`; the Ranch's effects are in `data/creatures/ranch.json`). Use `GameParty.max_size(d)` for the party's places, never the base setting, so the Hall counts. The House button on the life screen opens `ui/play/house_panel.gd`, which only calls `GameHouse.buy` and draws the rows; a row that cannot be built is disabled, with its reason shown as text under it.
- **Family tree.** `GameFamilyTree` (core, no UI) reads the dynasty's `history`, living heir and echoes into one entry per generation. Older heirs folded into the Ages are counted only. The chronicle's Family Tree tab (`ui/play/chronicle_panel.gd`) draws it; it has no tooltips, so the mobile suite needs nothing more.
- **Statistics.** `GameStats` (core, no UI) works out the dynasty's numbers from `GameAges` and the kept heirs. The chronicle's Statistics tab draws them. Each Age row keeps `gold_sum` and `gold_known` (the gold of its heirs at death), so the average per Age survives folding; the heirs kept in full also list their own gold.
- **Sex.** `GameSex` (core) gives every heir, spouse and child a sex: the founder picks it at the start, a spouse is always the opposite sex, and children are rolled from their own seeded dice (never the dynasty's main dice, so no life changes). Old saves are filled in on load (`GameDynasty._fill_sexes`). The golden digests drop the `sex` key (`Scen.drop_sex`, in place: copying would break the shared lists those digests rely on).
- **Accessibility.** Three yes-or-no options in `settings.cfg` (`UiSettings.ACCESS_KEYS`), set from the menu's Accessibility row. UI code takes colours from `Kit.good()`, `Kit.bad()` and `Kit.dim()`, never `Kit.GOOD`/`BAD`/`DIM` directly, and animations take their time from `UiSettings.motion_time()`.
- **Battle art.** The battle screen draws the hero, companions and foes from pixel sprites kept as text grids in `data/art/` (`docs/ART.md`), turned into textures by `ui/play/sprite_art.gd` (rendering only, cached). A figure is the class's 24x40 figure in the race's colours with the race's under and over layers, wearing a shirt from `data/art/shirts.json`: one picked from who they are unless the player chose one on the Looks panel (`ui/play/looks_panel.gd`, `GameDynasty.set_shirt`; saved as `shirt` only once chosen), and the heir in their gear: `data/art/gear.json` gives each weapon and armour a finish, a glow or a cape, and says per class where the weapon is and which palette keys are metal, leather, blade and wood. Art follows the style in `docs/ART_STYLE.md`, whose numbers are in `data/art/style.json` and checked by `SpriteArt.style_problems` (outline, stray pixels, colour cap, size, margins, standing on the ground; part of `SpriteArt.validate`, so `tools/check_data.gd` runs it); a new sprite must pass `tests/test_game_art_style.gd`. The textures `SpriteArt` hands out are regions of shared atlas pages (`ui/play/texture_atlas.gd`): use them as any texture, and wrap the building of a screen's many figures in `SpriteArt.begin_batch()`/`end_batch()` so the pages upload once. Anything without art keeps the old block. Each sprite figure stands in a `ui/play/figure_pose.gd` holder that breathes and plays the battle's events as moves (attack, cast, hurt, dodge, guard, fall), stilled by reduced motion. The fight is drawn in front of the land it happens in: `ui/play/scenery_art.gd` paints the place's scene from `data/art/scenery.json` (a scene per biome, place extras, weather and season layers) with its own dice seeded from the place, never the dynasty's. `tests/test_game_art.gd` checks every creature, class and race has art, `tests/test_game_gear.gd` the gear, `tests/test_game_poses.gd` the poses and `tests/test_game_scenery.gd` every place's scenery; `tools/art_sheet.gd` draws it all on one sheet.
- **Cosmetic randomness.** Anything the view randomises for show (a painted scene's scatter, particles, idle timing, camera shake) draws from `CosmeticRng` (`ui/play/cosmetic_rng.gd`: `keyed(key)` rolls the same every time, `loose()` differs each run), never from the dynasty's `rng` and never from Godot's global dice. `tests/test_game_cosmetic.gd` scans `ui/play` for both and plays fights through the battle screen to check they end exactly as the same fights with no view.
- **Touch.** `ui/play/touch_hint.gd` gives long-press previews on phones (`TouchHint.on_hover`). `ui/play/ui_settings.gd` stores the text size, the touch layout and the autopilot cooldowns in `user://settings.cfg`, not in the save. Touch targets are at least `touch_target_px` tall.

**Older prototype, not used by the game:** `core/battle`, `core/lineage`, `core/fate`, `core/economy`, `core/crafting`, `core/equipment`, `core/legacy`, `core/simulation`, `core/generation`, `world/`, `ui/screens`, `ui/components`, `ui/animations`, and the `tests/test_*.gd` files that don't start with `test_game_`. Nothing in the playable game refers to them. Don't extend them unless asked, and check before treating their tests as a gate.

## Conventions

- Old saves must keep loading. Missing keys fall back to defaults, and corrupt values must not crash loading, so check the type (for example `typeof(v) == TYPE_BOOL`) before using a saved value.
- A change that alters autopilot or auto-battle results is a balance change. Say so in the PR and show the before and after numbers.
- Commit the `.uid` file Godot generates beside each new script, so script references stay stable. Never commit anything under `.godot/`.
- Documentation: `docs/GDD.md` is the design, `docs/ROADMAP.md` lists what is done and what is next, and `docs/MOBILE.md` covers touch, text size and the Android and iOS export setup, `docs/BALANCE.md` covers the balance harness, `docs/ART.md` covers the battle sprites and their format, `docs/ART_STYLE.md` how new art should look, and `docs/RELEASING.md` covers publishing the APK and the Windows exe through GitHub. `TESTING.md` describes how the game's headless suites run. The `GutTest` files among the older prototype tests need an addon that isn't in this repo.
